# Phase 3, Plan 03 [cloud]: Custom folders follow the move, and old backups keep working

## Phase Goal

ROADMAP Goal line (verbatim): "PrintInvoicer becomes Billament everywhere (code, app, PDFs, scripts, docs, data folders
and the GitHub repository), existing users keep every job and finalized invoice through a one-time safe move of their
data, and the result ships as 4.0.0, so later phases are built under the new name from the start."

The Goal line is not a user story; this restates the part this plan delivers without adding scope (run
`/gsd-mvp-phase 3` to replace it with a canonical story if wanted):

**As a** user who set a backup or invoice folder inside `Documents\PrintInvoicer`, **I want** it to point at the same
place under `Documents\Billament` after the move, **so that** Back up now and Finalize keep working; and **I want** my
old daily backups to still show up, restore and age out, **so that** the rename does not cost me my backup history.

This plan delivers NAME-04 (D-13 and the backup-prefix discretion). It runs after 03-02 because it extends the same
`DataFolderMigration.Run` and the same AUDITING.md table.

**Path names in this plan:** every path uses the new `Billament.*` names. The old names appear only as values: the
legacy backup prefix, the picker pattern and test data; they are deliberate (D-19).

<assumption_delta_decision>
The assumption-delta scan of the Phase 3 roadmap section fired on "a custom backup or invoice folder" (kind: chosen).
- Primary noun: the data folder, `Documents\Billament` (derived from Documents plus the app name, as before).
- Decision: no-change. The two folder settings were already chosen by the user before this phase; the move does not
  turn a derived value into a chosen one. It only re-anchors a chosen value that pointed inside the old data folder,
  once, and leaves every other value alone.
- Nothing would force a later promote: no second data folder or second source of truth is introduced.
</assumption_delta_decision>

<objective>
Where it runs: [cloud] (Core code and Linux tests; the picker string is compile-checked here and used on Windows in 03-05).

Rewrite the two folder settings inside the moved database when they point into the old folder (raw SQL, two rows at
most, comparison passed in), and make `DatabaseBackup` list, restore and prune backups made under the old name by the
date in their names, with the restore picker showing both names.

Purpose: NAME-04, ROADMAP success criterion 2 ("a custom backup or invoice folder inside the old folder still points at
the moved files").
Output: `RemapFolder` and the settings rewrite in `DataFolderMigration`, legacy prefix handling in `DatabaseBackup`, the
picker filter, tests, AUDITING.md row and "There are 36 tags".
</objective>
