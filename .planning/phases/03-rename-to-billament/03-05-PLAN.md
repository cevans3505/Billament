# Phase 3, Plan 05 [windows]: Windows checks and the real upgrade test

## Phase Goal

ROADMAP Goal line (verbatim): "PrintInvoicer becomes Billament everywhere (code, app, PDFs, scripts, docs, data folders
and the GitHub repository), existing users keep every job and finalized invoice through a one-time safe move of their
data, and the result ships as 4.0.0, so later phases are built under the new name from the start."

The Goal line is not a user story; this restates the part this plan proves without adding scope (run
`/gsd-mvp-phase 3` to replace it with a canonical story if wanted):

**As a** user upgrading from 3.7.0 on Windows, **I want** the real 4.0.0 exe to move my real data safely, and to stop
with a plain message when 3.7.0 is still open, **so that** I can trust the upgrade before it is published.

This plan is the Windows half of D-20 and the first part of the D-21 checklist: the screen tests, the README pictures,
`publish.ps1`, and the upgrade test on a copy of real 3.7.0 data. The cloud could compile the App but could not run
WPF, PowerShell or the real exe.

**Path names in this plan:** the new `Billament.*` names. Old names appear only as the 3.7.0 data and program that the
test upgrades from.

<objective>
Where it runs: [windows] (the user's Windows PC: offscreen UI tests, README pictures, publish.ps1, the real upgrade test).

Run every check that needs Windows: the full test suite with the offscreen screen tests, `make-readme-images.ps1`,
`publish.ps1` (install plus the old-install cleanup), and then the user's upgrade test of the 4.0.0 exe against a copy
of a real 3.7.0 data folder, including the "3.7.0 still running" failure and custom folders inside the old folder.

Purpose: verify on the real platform what the Linux tests could only simulate (RESEARCH A4, A5; Pitfall 2).
Output: test and script results recorded in 03-05-SUMMARY.md; README pictures committed only if they really changed;
the upgrade test results recorded by the user.
</objective>
