# Phase 2, Plan 04: Safe invoice file names, and Explorer paths passed as single arguments

## Phase Goal

ROADMAP Goal line (verbatim): "The concerns with the best benefit for the cost (triage score 2.0 and above) are fixed in
score order, so releases can be checked, invoices already sent are guarded by a test, and paths, file names and update
checks are handled safely."

The Goal line is not a user story; the stories below restate the parts this plan delivers without adding scope. Run
`/gsd-mvp-phase 2` to replace them with canonical stories if wanted.

**As a** PrintInvoicer user, **I want** invoice PDFs named safely whatever I type as the job title or invoice number,
**so that** a PDF is always saved in my invoice folder and never fails because of a reserved or overlong name.
**As a** PrintInvoicer user, **I want** the Open buttons and the error report to open Explorer at the right place even
when a path holds a quote or space, **so that** a path can never turn into extra Explorer switches.

This plan delivers FIX-06 (C14) and FIX-03 (C06), both scored 2.00 (equal scores, so their order does not matter).
FIX-06 is the tracer: its slice crosses Core, App and tests and carries the most risk (it decides every invoice file
name). It runs in Wave 3 because it edits AUDITING.md after plan 02-03 and keeps the tag count 02-03 set (27).

<objective>
Add `SafeFileName` to Core (fixed character list, dot runs, trim, `untitled` fallback, reserved device names, UTF-16

in `InvoicePdf.Write` through it, and test it on Linux. Then add `ShellCommands` to Core so the two Explorer call sites
pass paths through `ProcessStartInfo.ArgumentList`, with Linux tests.

Purpose: paths and file names built from user data are handled safely.
Output: `SafeFileName`, `ShellCommands` and their tests; `InvoicePdf.Write`, `SettingsViewModel.OpenFolder` and
`ErrorReport.Show` wired to them; AUDITING.md notes.

1. New file `src/PrintInvoicer.Core/Files/SafeFileName.cs`, namespace `PrintInvoicer.Core.Files` (new folder `Files`,
   matching the namespace). `public static class SafeFileName` with summary "File names built from things the user
   typed (an invoice number, a job title), made safe for Windows and length-limited. Never throws for any text, so a
   strange title can never stop an invoice being saved." Members:
   - `public const int MaxTitleLength = 60;`, `public const int MaxNumberLength = 30;`,
     `public const int MaxNameLength = 120;`, `public const string Fallback = "untitled";`, each with a one-line summary.
   - A private static readonly set of the characters Windows forbids in a name: `< > : " / \ | ? *`. Use this fixed
     list, not the operating system's list (`Path.GetInvalidFileNameChars()` returns only two characters on Linux, so the
     same title would come out differently in tests and in the app; RESEARCH FIX-06).
   - A private static readonly `HashSet<string>` with `StringComparer.OrdinalIgnoreCase` of reserved device names: CON,
     PRN, AUX, NUL, COM0 to COM9, LPT0 to LPT9, COM and LPT followed by superscript one, two or three (write them with
     the escapes `\u00B9`, `\u00B2`, `\u00B3` so the source stays ASCII), CONIN$ and CONOUT$.
   - `public static string Clean(string? text, int maxLength)` with summary "The text as one safe name part: forbidden
     and control characters become a dash, runs of dots become one dot, spaces and dots are trimmed from both ends, a
     reserved device name gets a leading underscore, and the result is at most maxLength chars without splitting a
     character. Empty results become Fallback." Throw `ArgumentOutOfRangeException` when `maxLength` is below
     `Fallback.Length` (a programmer error, never caused by text). Steps, in this order: null becomes empty; replace
     each forbidden character, each `char.IsControl` character and each unpaired surrogate (a high surrogate not
     followed by a low one, or a low one not after a high one) with `-`; collapse every run of two or more `.` into one
     `.`; trim `' '` and `'.'` from both ends; if longer than `maxLength`, cut to `maxLength`, drop one more char when the
     last kept char is a high surrogate, and trim trailing spaces and dots again; if empty, return `Fallback`; if the
     part before the first `.` (with trailing spaces removed) is a reserved name, put `_` in front, and if that makes it
     longer than `maxLength`, cut it again the same way.
   - `public static string Compose(string prefix, string? number, string? title, string suffix)` with summary "An
     invoice file name: prefix, the cleaned number, the cleaned title, then the suffix, such as "Invoice 2026-001 Tube
     caps (detail).pdf". The prefix and suffix are fixed text from code, not user data." Throw `ArgumentException` when
     `prefix` is empty or whitespace, or when `prefix.Length + suffix.Length + MaxNumberLength + MaxTitleLength + 2`
     exceeds `MaxNameLength` (programmer errors). Return
     `$"{prefix} {Clean(number, MaxNumberLength)} {Clean(title, MaxTitleLength)}{suffix}"`.
