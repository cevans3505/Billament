# Phase 2, Plan 01: Guard invoices already sent with a legacy-database test, and record the re-scores

## Phase Goal

ROADMAP Goal line (verbatim): "The concerns with the best benefit for the cost (triage score 2.0 and above) are fixed in
score order, so releases can be checked, invoices already sent are guarded by a test, and paths, file names and update
checks are handled safely."

The Goal line is not written as a user story. The stories below restate its outcomes without adding scope. Run
`/gsd-mvp-phase 2` to replace them with canonical stories if wanted.

**As the** maintainer, **I want to** open a database from before price snapshots existed in a test and see every
finalized invoice frozen once at its old total, **so that** a later change (such as Phase 3's FIX-08) cannot silently
change a total a customer already has.
**As the** maintainer, **I want** the triage file to say what the code showed for each Phase 2 concern, **so that** the
scores stay honest and nothing already handled gets changed for nothing.

This plan delivers FIX-02 (C27, score 2.50, the second item in score order) and the TRIA-01 re-score notes (ROADMAP
success criterion 1). It changes no production code.

Purpose: invoices already sent are guarded by a test before Phase 3 changes the freeze path.

  Phase 3.

## AUDIT tags in test code (convention, stated explicitly)

CLAUDE.md asks for an AUDIT comment and an AUDITING.md row on every new line that reads, writes or deletes a file. This
repository applies that rule to `src` and to test code whose output stays after the test run; test scaffolding kept
inside its own temporary folder or the test output folder is not tagged. Evidence, checked on 2026-11-02 at fade8d5:

- Nine unit-test files in `tests/PrintInvoicer.Tests` (BackupTests, BambuFileReaderTests, BambuRobustnessTests,
  DatabaseTests, FinalizeTests, GooRobustnessTests, PriceSnapshotTests, PricingRulesTests, ResinTests) create, write and
  delete files under `Path.GetTempPath()` with no tag (for example `PriceSnapshotTests` builds `pi-snap-<guid>.db` there
  and deletes it in `Dispose`).
- The only AUDIT comments under `tests` are in `tests/PrintInvoicer.UiTests/WpfHost.cs` (screenshots) and
  `tests/PrintInvoicer.UiTests/ReadmeImageTests.cs` (README pictures), which keep their output after the run.
- AUDITING.md "Building and releasing" names exactly those two files as the tagged test code, outside the `src` count.

So this plan's test file access (reading the fixture from the test output folder, and writing then deleting its own
temporary database under `Path.GetTempPath()`) gets no tag, and the `src` tag count is unchanged. A test that wrote
anywhere else (for example the real Documents folder) would need a tag and a row. CLAUDE.md is not changed by this phase.
