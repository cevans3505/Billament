# Phase 2, Plan 03: Capped update-check reply, and backup copies that never share a temporary file

## Phase Goal

ROADMAP Goal line (verbatim): "The concerns with the best benefit for the cost (triage score 2.0 and above) are fixed in
score order, so releases can be checked, invoices already sent are guarded by a test, and paths, file names and update
checks are handled safely."

The Goal line is not a user story; the stories below restate the parts this plan delivers without adding scope. Run
`/gsd-mvp-phase 2` to replace them with canonical stories if wanted.

**As a** PrintInvoicer user, **I want** the update check to read only a small, bounded reply from GitHub, **so that** a
huge or broken reply can never slow down or crash the app; it just shows no update bar.
**As a** PrintInvoicer user, **I want** every backup copy to use its own temporary file, **so that** a double click on
Back up now or a backup during startup can never spoil another copy or delete a file it did not make.

This plan delivers FIX-05 (C10) and FIX-04 (C09), both scored 2.00. FIX-05 is the tracer because it is the slice that
crosses Core, App and tests (the Core reader is tested on Linux; the App wiring is compile-checked on Linux and run on
Windows). It runs in Wave 2 because it edits AUDITING.md after plan 02-02.

<objective>
Read GitHub's latest-release reply through a Core helper that never takes more than 256 KB and returns null ("no update
information") when the reply is bigger, wire `UpdateService` to it, and test the cap and hostile replies on Linux. Then
give each database backup copy its own temporary file and delete only that file on failure, with the missing AUDIT tag
added and AUDITING.md updated.

Purpose: update checks and backups handle odd input and timing safely.
Output: new `LatestReleaseReply` and its tests; changed `UpdateService.FetchLatestAsync`, `FetchAndRememberAsync`,
`DatabaseBackup.Copy`; four new `BackupTests`; AUDITING.md updated (27 tags).
</objective>
